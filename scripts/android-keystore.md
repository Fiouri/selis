# Android signing keys — what the owner runs

Decision (owner, 2026-10-15; ADR 0025): **one app signing key on every channel** (GitHub
Releases / Obtainium, IzzyOnDroid, F-Droid, and Google Play through "use my own key") and a
**separate Play upload key**. Android installs an update only when it carries the same signing
certificate as the installed app, so with one key a user can move between Play, GitHub and
F-Droid installs without uninstalling (and losing the library).

| Key | File / alias | Signs | Who holds it |
| --- | --- | --- | --- |
| App signing key | `selis-release.jks` / `selis` | Every APK we publish (GitHub release, IzzyOnDroid, F-Droid via apksigcopier); Play re-signs Play installs with its copy | You (offline backups), GitHub secrets, Google (one encrypted copy via PEPK) |
| Upload key | `selis-upload.jks` / `selis-upload` | Only the AAB sent to Play | You, GitHub secrets. Google knows only its certificate |

The keystores are made on your machine and go straight into the GitHub secrets and your
backups. They never enter the repository, a chat, a log or an issue. Without the secrets the
release workflow (`.github/workflows/release-android.yml`, ADR 0021) still builds and checks
everything and leaves the artifacts unsigned (a notice says so); without the upload key the AAB
stays unsigned.

Requirements checked 2026-10-15 (Play Console Help, "Use Play App Signing",
<https://support.google.com/googleplay/android-developer/answer/9842756>): the upload key is in a
Java keystore and is "an RSA key of 2048 bits or more"; a custom app signing key is "RSA 2048-bit
or higher" (Google's own keys are RSA 4096). New apps are enrolled by default in "quantum-ready
hybrid signing with Google-generated keys"; you change that **before a release rolls out to open
testing or production** (step 5; do it before the very first release of any kind, so no tester
ever installs a build signed with Google's key). We use RSA 4096 and 10 000 days (27 years) of
validity for both keys; Android checks expiry only at install time, but Play has long required
validity past 2033.

Everything below runs in **PowerShell**, in a folder **outside the repository** (for example
`D:\keys`), with JDK 17's tools on the PATH
(`$env:Path = "C:\Program Files\Eclipse Adoptium\jdk-17*\bin;$env:Path"` or the full path).

## 1. App signing key

```powershell
keytool -genkeypair -v -keystore selis-release.jks -storetype PKCS12 `
  -alias selis -keyalg RSA -keysize 4096 -sigalg SHA256withRSA -validity 10000 `
  -dname "CN=Any WeCon, O=Any WeCon, C=GR"
```

It asks for a password twice (PKCS12: the store and the key share it). Use a long random one
generated by your password manager and stored there under "Selis app signing key".

## 2. Upload key

```powershell
keytool -genkeypair -v -keystore selis-upload.jks -storetype PKCS12 `
  -alias selis-upload -keyalg RSA -keysize 4096 -sigalg SHA256withRSA -validity 10000 `
  -dname "CN=Any WeCon upload, O=Any WeCon, C=GR"
keytool -export -rfc -keystore selis-upload.jks -alias selis-upload -file selis-upload.pem
```

A different password from step 1 ("Selis upload key" in the password manager).
`selis-upload.pem` is the public upload certificate Play asks for in step 5.

## 3. Fingerprints (public)

```powershell
keytool -list -v -keystore selis-release.jks -alias selis | Select-String "SHA256:"
keytool -list -v -keystore selis-upload.jks -alias selis-upload | Select-String "SHA256:"
```

The app signing key's SHA-256 goes, lowercase hex without colons, into F-Droid's
`AllowedAPKSigningKeys`, the IzzyOnDroid request and the website's download page. Set the
website variable yourself or send me only that line:

```powershell
$fp = ((keytool -list -v -keystore selis-release.jks -alias selis | Select-String "SHA256:").ToString() -replace '.*SHA256:\s*','' -replace ':','').ToLower()
gh variable set SELIS_APK_CERT_SHA256 -R Fiouri/selis --body $fp
```

## 4. GitHub secrets

`gh` reads secret values from stdin or prompts for them, so nothing lands in the shell history:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("selis-release.jks")) | gh secret set ANDROID_KEYSTORE_BASE64 -R Fiouri/selis
gh secret set ANDROID_KEYSTORE_PASSWORD -R Fiouri/selis   # paste the step-1 password at the prompt
gh secret set ANDROID_KEY_PASSWORD -R Fiouri/selis        # the same password (PKCS12)
gh secret set ANDROID_KEY_ALIAS -R Fiouri/selis --body selis

[Convert]::ToBase64String([IO.File]::ReadAllBytes("selis-upload.jks")) | gh secret set ANDROID_UPLOAD_KEYSTORE_BASE64 -R Fiouri/selis
gh secret set ANDROID_UPLOAD_KEYSTORE_PASSWORD -R Fiouri/selis   # the step-2 password
gh secret set ANDROID_UPLOAD_KEY_PASSWORD -R Fiouri/selis        # the same password (PKCS12)
gh secret set ANDROID_UPLOAD_KEY_ALIAS -R Fiouri/selis --body selis-upload
```

Check (names only, values are never shown): `gh secret list -R Fiouri/selis`.

## 5. Play: use our app signing key (PEPK), register the upload key

When the app exists in Play Console (needs the developer account), **before any release**:

1. Play Console › Selis › **Protected with Play › Play Store distribution › Go to Play app
   signing** (older menus: Test and release › App integrity › App signing).
2. **Change the app signing key** › **Provide a copy of your app signing key** › "Export and
   upload a key from Java keystore".
3. Download **`pepk.jar`** and the **encryption public key** (`encryption_public_key.pem`) the page
   offers into `D:\keys`.
4. Run the command the page shows; with our names it is:

   ```powershell
   java -jar pepk.jar --keystore=selis-release.jks --alias=selis `
     --output=selis-signing-key.zip --include-cert --rsa-aes-encryption `
     --encryption-key-path=encryption_public_key.pem
   ```

   If the console's command differs (flags change), the console's wins. PEPK prompts for the
   step-1 password. If it fails with "Cannot find any provider supporting
   RSA/NONE/OAEPWithSHA1AndMGF1Padding", run it with a full JDK 21 (Temurin) `java`.
5. Upload `selis-signing-key.zip` (the private key encrypted for Google only).
6. **Upload key:** the same page asks for the upload certificate: upload `selis-upload.pem`.
7. Delete `selis-signing-key.zip` and `pepk.jar`.

Check on the App signing page: "App signing key certificate" SHA-256 = step 3's app signing
fingerprint; "Upload key certificate" SHA-256 = step 3's upload fingerprint.

## 6. Backup (do this before step 5 and before the first release)

**Losing the app signing key means no updates ever again for GitHub, IzzyOnDroid and F-Droid
users** — they would have to uninstall (losing the library unless they move it first) and
install an app signed with a new key. Play users keep updating (Google holds a copy and can
rotate it), and a lost or leaked upload key can be reset through Play Console (App signing ›
"Request upload key reset"); the app signing key has no such path outside Play.

- **Two offline copies** of `selis-release.jks` and `selis-upload.jks`: two encrypted USB sticks
  (BitLocker To Go / VeraCrypt), kept in **two different places** (e.g. home and office or a
  relative's), never on a cloud-synced folder.
- **Password manager:** both passwords, the aliases, the SHA-256 fingerprints and the creation
  date; the password manager's emergency-access / recovery kit set up so the key survives you
  being unavailable.
- Once a year: open each copy and run `keytool -list -keystore selis-release.jks` with the stored
  password, to prove the backup and the password still match.
- Then delete the working copies in `D:\keys` (unless `D:\keys` is one of the encrypted copies).

## 7. Check

Run the workflow by hand (Actions › Android release › Run workflow); a tag is pushed only after
you say so. "Sign" must print `signed …` for the six APKs and the AAB, and "Signature checks"
must pass (APK Signature Scheme v2 + v3 with the app signing certificate, jarsigner with the
upload certificate for the AAB).
