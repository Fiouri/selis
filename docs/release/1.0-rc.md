## P5b (2026-10-15): debug suite after the pre-RC fixes

Debug builds of the final P5b commit (contrast tokens #50, user-initiated transfer jobs #51,
TalkBack fixes #52, Scan a photo) on both devices, 22 flows each (the 19 Tier 2 flows,
transfer-background, pages drag): **all pass on the S23 and on the AVD.** Notes from getting
there, none of them app defects:

- Three flows first failed after the TalkBack fixes because Maestro's WebView hierarchy takes an
  `aria-label` as the element's id before `data-testid` (`theme-choice-*`, `delete-dialog`) and a
  document card's longer name (pages); fixed in the components and the flow (ADR 0028).
- The 3 GB AVD fills its RAM and swap after ~2 h of these flows (system_server restarted once,
  load > 6); a cold boot of the emulator before the rerun cleared every failure it caused.
- Another session's builds on this machine restarted the adb server mid-run; the runs it cut were
  repeated.

## Accessibility

**TalkBack walkthrough (P5b, 2026-10-15, Galaxy S23, Samsung TalkBack 16.2, debug builds).**
Device lock taken; TalkBack enabled over adb and restored afterwards (service list, its "Display
speech output" and log level back to what they were). How: TalkBack follows keyboard focus, so
each screen was walked with `adb shell input keyevent TAB`, with TalkBack's spoken text shown on
screen ("Display speech output") and captured with the focus box after every step
(`.tmp/p5b/tb/walk.sh`). Screens: library, viewer, annotate, sign (+ new signature), transfer
(send), settings, scan, OCR options.

| Finding (before) | Fix (P5b, ADR 0028) | After |
| --- | --- | --- |
| Switches had no name: "Off, Switch" (send history, pack, settings, tools, OCR) — Chrome on Android does not hand an `aria-labelledby` name to TalkBack (the tree had it) | `aria-label` on switches, and likewise on sheets, dialogs, radio groups and the note editor (all named by `aria-labelledby` before) | "Off, Local network only, No relay. Transfers work only on the same Wi‑Fi., Switch"; sheets: see below |
| Document cards: "2 pages · Today, Open Lease agreement, Button" — the `aria-describedby` meta first | one name, verb and title first | "Open Lease agreement, 2 pages · Today, Button, 1 of 4" |
| Library filters, annotate/redact tools, scan filters: "checked, All, Switch" (`aria-pressed` reads as a switch) | radio groups; page selection in the grid is a checkbox | "Checked. In group, option 1 of 3, All, Radio button" |
| Viewer pages: just "region" | a named group | "Trip to Crete" and the page text |
| **Scan: focus went behind the camera** to the library's hidden Search, Sort, filters and tab bar | Scan and Images → PDF are full-screen layers outside `#root`, which is inert meanwhile | Tab stays on Close and the shutter |

Order: top to bottom on every screen (header, filters, cards, floating buttons, tab bar; viewer
header, dock, pages); sheets keep focus inside until closed; the cycle returns to the start (no
trap). Not covered by this method: TalkBack does not voice keyboard focus inside sheets and
dialogs (it announced "Selis" while the focus box moved correctly), so their content was checked
in the accessibility tree instead; swipe gestures injected over adb are not seen by TalkBack, so
reading order of non-focusable text follows the DOM order checked in the tree. A walkthrough
with a person listening is still worth doing once on a release build.
